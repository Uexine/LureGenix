# Безопасность

- HTTP по умолчанию доступен только на 127.0.0.1:8080. Доступ извне:
  SSH-туннель либо HTTPS. Проверку сертификата агента отключать нельзя.
- Пароли хешируются bcrypt; административные API и WebSocket требуют JWT.
  Сессия действует один час. Смена пароля не отзывает ранее выданный JWT.
- Общий AGENT_SECRET используется при регистрации. Каждый агент получает
  собственную случайную идентичность; чужие задания и события запрещены.
- Backend работает без root и capabilities, с read-only файловой системой.
  БД и внутренние API не публикуют порты; роль приложения не является superuser.
- Агент проверяет путь, SHA-256 и разрешенные каталоги. Существующие файлы
  не перезаписывает, симлинки не принимает. Критичные системные конфиги и
  исполняемые расширения запрещены; сгенерированное содержимое не выполняется.
- Агент работает от root. Сужайте AGENT_ALLOWED_DIRS под целевой сервер.
  Компрометация root-хоста выходит за границы защиты.
- inotify не определяет достоверный PID/UID и не гарантирует обнаружение
  каждого чтения через mmap/NFS. Потерю очереди агент сообщает как monitor_error.
- Реакция: журнал, уведомление и подтверждение администратором.
  Автоматической блокировки пользователей и процессов нет.
- Защищайте .env, журнал агента и резервные копии. Ранее опубликованные
  секреты нужно заменить: исключение файла из Git не очищает историю.
- Перед обновлением сделайте резервную копию БД. Не используйте
  `docker compose down -v`: команда удаляет тома.
- Удаление агента не удаляет приманки. Не удаляйте его журнал, пока файлы
  требуют мониторинга. При длительном offline контролируйте место на диске.

## HTTPS

Поместить сертификат и ключ в `certs/server.crt` и `certs/server.key`
(ключ доступен только владельцу). Сертификат должен содержать нужное DNS-имя/IP.

```bash
docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d
```

HTTPS: `https://SERVER_IP:8443`. HTTP остается на loopback при
`BIND_ADDRESS=127.0.0.1`. Для собственной CA у агента задается `AGENT_CA_FILE`;
в `tools/configure_agent.py` и `tools/smoke_test.py` предусмотрен `--ca-file`.

Резервная копия БД, выполняется из корня проекта в Bash:

```bash
umask 077
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > backup.sql
```

Сетевые настройки, восстановление БД и inotify требуют проверки на реальном Linux.
